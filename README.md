# REST Test Client

Простой REST-клиент с веб-интерфейсом: отправка запросов GET/POST/PUT/DELETE, тело запроса, аутентификация через Keycloak или ручные заголовки, история URL, отображение ответа в виде JSON и таблицы.

- **Стек:** Bun (сервер + API), React + Vite (фронтенд)
- **Порт по умолчанию:** 5335 (настраивается через `PORT`)
- **История:** последние 20 URL (настраивается через `HISTORY_SIZE`)

## Требования

- Для локальной разработки и сборки: [Bun](https://bun.sh/) или Node.js 18+
- **На проде с Node 10 (или другой старой Node): сборку на хосте не запускайте** — используйте только Docker (см. ниже)

## Установка

```bash
bun install
cd frontend && bun install && cd ..
```

## Конфигурация

Скопируйте `.env.example` в `.env` и при необходимости измените:

- `PORT` — порт веб-интерфейса (по умолчанию 5335)
- `HISTORY_SIZE` — сколько последних URL хранить в истории (по умолчанию 20)

## Запуск

1. Собрать фронтенд (один раз или при изменениях):

```bash
bun run build
```

2. Запустить сервер:

```bash
bun start
```

Откройте в браузере: **http://localhost:5335**

## Запуск в Docker (рекомендуется для продакшена)

На сервере с **Node 10** (или без Bun) не запускайте `bun run build` / `npm run build` — Vite и TypeScript требуют современный Node. Собирайте и запускайте приложение **только через Docker**: сборка фронтенда выполняется внутри образа на Node 20, на хосте не нужны ни новая Node, ни Bun.

### Сборка образа

```bash
docker build -t rest-test-client .
```

### Запуск контейнера

Стандартный порт (5335):

```bash
docker run --rm -p 5335:5335 rest-test-client
```

Кастомный порт и параметры истории:

```bash
docker run --rm \
  -e PORT=8080 \
  -e HISTORY_SIZE=50 \
  -p 8080:8080 \
  rest-test-client
```

После запуска откройте: `http://localhost:5335` или другой порт, который вы пробросили.

На проде с Node 10 достаточно установленного **Docker**: при `docker build` фронтенд собирается внутри контейнера на Node 20, рантайм — Bun в своём образе. Версия Node на хосте не используется.

### Режим разработки

- Сервер с автоперезагрузкой: `bun run dev`
- Фронтенд с hot-reload (прокси на API 5335): `bun run frontend:dev` — интерфейс будет на http://localhost:5336

## Пайплайн запроса (от клиента до целевого API и обратно)

1. **Браузер (React)** — пользователь нажимает «Отправить». Формируется тело: `{ url, method, headers?, body?, keycloak? }`. Отправляется **POST /api/execute** на наш сервер (порт 5335).

2. **Bun-сервер (server.ts)** — принимает запрос на `/api/execute`, парсит JSON. Если передан **keycloak** — запрашивает токен у Keycloak (`getKeycloakToken`), подставляет **Authorization: Bearer &lt;token&gt;** в заголовки. Иначе используются только переданные вручную заголовки.

3. **Прокси-запрос к целевому API** — сервер выполняет **fetch(url, { method, headers, body })** к указанному пользователем URL (внешний API). Исходный запрос идёт с нашего сервера, поэтому обходится CORS и можно слать запросы к любым доменам.

4. **Ответ целевого API** — сервер читает `status`, `statusText`, заголовки и тело ответа, добавляет URL в **историю** (`addToHistory`), возвращает клиенту JSON: `{ status, statusText, headers, body, contentType }`.

5. **Браузер** — получает ответ от `/api/execute`, пишет запись в **логи**, показывает результат в блоке «Ответ» (JSON / таблица) или выводит ошибку (сеть, 4xx/5xx от API, ошибка Keycloak).

Итого: **браузер → наш API (5335) → [опционально Keycloak за токеном] → целевой URL → ответ целевого API → наш API → браузер**.

## Возможности

- **URL и параметры** — ввод полного пути с query-параметрами
- **Метод** — GET, POST, PUT, DELETE
- **Тело запроса** — JSON для POST/PUT
- **Аутентификация:**
  - **Keycloak** — URL сервера, realm, client id/secret, логин и пароль; токен запрашивается автоматически и подставляется в заголовок `Authorization`
  - **Ручные заголовки** — произвольные пары «имя — значение»
- **История** — последние N введённых URL, выбор из списка подставляет URL в форму
- **Ответ** — вкладки «JSON» (отформатированный) и «Таблица» (массив или объект из JSON отображаются таблицей)
- **HTTPS с самоподписанными/внутренними сертификатами** — при ошибке «unable to verify the first certificate» включите опцию «Не проверять сертификат SSL» (только для тестовых окружений)

История сохраняется в `data/history.json`. По желанию пароли и токены в истории можно шифровать: задайте в `.env` переменную `HISTORY_ENCRYPTION_KEY` (32 байта в base64 или 64 символа hex, например `openssl rand -base64 32`). Тогда в файле будут зашифрованы: пароль и client secret Keycloak, значение заголовка Authorization.
